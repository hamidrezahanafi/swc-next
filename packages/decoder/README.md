# `@swc-next/decoder`

Decodes the binary output of an SWC Next parser crate into an ESTree-compatible program, comments, and parser diagnostics.

The binary format is internal and versioned with the Rust crates. Depend on the exact package version that matches the `swc_next_*` crate versions used by your native binding.

```js
import { decode } from "@swc-next/decoder";
import { parseSync as __parseSync } from "./binding.js";

export function parseSync(source, options) {
  const sourceBuffer = new TextEncoder().encode(source);
  const buffer = __parseSync(sourceBuffer, source.length, options);
  return decode(buffer, source, sourceBuffer);
}
```

`decode` selects the JavaScript or TypeScript decoder from the buffer header. `decodeJs` and `decodeTs` are also exported for callers that already know the language.

For lazy AST nodes, import the matching API from `@swc-next/decoder/lazy`:

```js
import { decode, encodeOptions } from "@swc-next/decoder/lazy";
```

This entry exports `decode`, `decodeJs`, `decodeTs`, and `encodeOptions` with the same
arguments as the default entry. Accessing `program` creates its wrapper; node
fields and array elements are decoded on access, with strings, nodes, and arrays
cached on first access. Repeated reads return the same nodes and arrays. Getter
fields and node array entries are read-only. The input buffers must remain
unchanged while the result is in use.

Arrays support indexing, iteration, and ordinary array read methods, including
`Array.isArray`. Nodes expose fields through prototype getters. Use `toJSON()`
for a shallow plain object or `JSON.stringify()` to traverse the tree with the
same ESTree fields as the default decoder. As with the default decoder, BigInt
values need a replacer when serializing to JSON. Comments and diagnostics retain
the default entry's lazy result getters.

Both decoder variants are generated by `cargo run -p ast_tools`; update their
schema or generators instead of editing the generated files.
